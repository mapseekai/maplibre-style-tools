# Unified AI tools migration

## Breaking release

This is a **breaking `0.x` minor API change**. There are no legacy aliases,
compatibility fallbacks, deprecated input parsers, or supported deep imports for
the removed AI factories. Move AI integrations to the single `/ai` entry point,
then replace factory keys and string-encoded JSON fields according to this
guide.

## Import cutover

```ts
import { createMapLibreStyleTools } from 'maplibre-style-tools/ai';
```

| Existing public import/export | Release status and replacement |
|---|---|
| Root `createMapLibreStyleTools` | Removed. Import `createMapLibreStyleTools` from `maplibre-style-tools/ai`. |
| Root `CreateMapLibreStyleToolsOptions` and `MapAccessor` | Removed. Import the same-named types from `/ai`. |
| Root `StyleAccessor` | Removed with `getState`; no replacement. |
| Root `ToolCallResult` | Removed. Use `/ai` `AiStyleToolResult`; it has no top-level `style`. |
| Root `createCompactMapLibreStyleTools` | Removed; use the single `/ai` factory. |
| Root `FULL_LEGACY_TOOL_NAMES` and `/ai` `COMPACT_LEGACY_TOOL_NAMES` | Removed; no replacement. The migration matrix is the published mapping. |
| Root legacy `StyleOperation` and `StyleOperationResult` | Removed. Use `/core` `StyleOperation`/`StyleTransactionResult` for direct transaction code, or `/ai` `AiStyleToolResult` for AI calls. |
| Existing `/core`, `/maplibre`, `/mcp`, and `/bridge` APIs | Retained and tested as non-AI entry points; they must not re-export removed full/compact factory symbols. |

## Five-tool contract

`createMapLibreStyleTools(options)` returns exactly these five AI SDK tools:

- `inspectStyle`
- `applyStyleTransaction`
- `applyStyleDocument`
- `runMapCommand`
- `queryMapFeatures`

Each is an AI SDK tool. Pass the object to an AI SDK `tools` set, or invoke
`.execute(input)` directly; it always returns a `Promise` of a discriminated
`AiStyleToolResult`. Inputs are closed native JSON objects: unknown keys and
removed string-JSON fields fail with `INVALID_INPUT` before handler, Map, image
loader, or runtime-command access. Named domain maps such as `paint`, `layout`,
metadata, and GeoJSON properties remain native JSON values, not stringified
escape hatches.

## Removed string-JSON fields

No unified action declares a legacy string-JSON field. Every field in this table
is rejected as `INVALID_INPUT` even when its string contents would otherwise
parse. The table is exhaustive for the 23 removed AI input fields.

| Removed field | Former capability family | Native structured replacement |
|---|---|---|
| `operationsJson` | Compact operation batches | `transaction.operations: StyleOperation[]`. |
| `layerIdsJson` | Compact layer inspection | `layerIds: string[]`. |
| `patchJson` | Layer/source patch tools and compact transaction validation | `deepMergeLayerDefinition.patch`, `deepMergeSourceDefinition.patch`, `patchSource.patch`, or `validateTransaction.transaction`. |
| `valueJson` | Single layer property and global-state edits | A `paint`/`layout` property value inside `setLayerProperties`, or native `setGlobalState.value`. |
| `propertiesJson` | Batch paint/layout edits | Native `paint` or `layout` record inside `setLayerProperties`. |
| `filterJson` | Layer and feature filtering | Native `setLayerFilter.filter`, `setGeoJsonSourceFilter.filter`, or query `filter: JsonValue[]`; use `mode: 'clear'` rather than a JSON `null` string. |
| `layerJson` | Add/replace layer | `addLayerDefinition.layer` or `replaceLayerDefinition.layer`. |
| `sourceJson` | Add/replace source | `addSource.source` or `replaceSourceDefinition.source`. |
| `dataJson` | GeoJSON source updates | `setGeoJsonData.data` for setData, or `updateGeoJsonData.diff` for updateData. |
| `optionsJson` | GeoJSON cluster options | Native `patchSource.patch`. |
| `styleJsonOrUrl` | Whole-style application | `source: { kind: 'style', style }` or `source: { kind: 'url', url }`. |
| `styleJson` | Document validation | `validateDocument.style`. |
| `metadataJson`, `transitionJson`, `lightJson`, `skyJson`, `projectionJson`, `terrainJson` | Root Style mutation | Native root-property operation values. |
| `glyphsUrlJson`, `spriteUrlJson` | Glyph and sprite root URLs | Native nullable `setStyleRootProperties.properties.glyphs` or `.sprite` values. |
| `centerJson` | Camera defaults | Native `setStyleRootProperties.properties.center` two-number coordinate array. |
| `targetJson`, `stateJson` | Feature-state updates | Native `target` and `state` objects of the corresponding runtime command. |

An ordinary URL remains a scalar string in an explicitly named URL field. It is
never accepted as a JSON-encoded object or array.

## GeoJSON setData/updateData split

The legacy `updateGeoJsonSourceData` capability becomes two native paths:

- Map `method: 'setData'` to `applyStyleTransaction` with
  `{ op: 'setGeoJsonData', sourceId, data }`. Use it for a native GeoJSON or URL
  replacement.
- Map `method: 'updateData'` to `runMapCommand` with
  `{ action: 'updateGeoJsonData', sourceId, diff }`. Use it for a native
  incremental GeoJSON diff.

Do not route the `updateData` diff through the document transaction.

## No-op transaction behavior

`applyStyleTransaction` accepts `transaction: { operations: [] }` as an
explicit wrapper-handled no-op. It does not invoke Map, core, or runtime
authority: `noOp` is `true`, `applied` is `false`, `changedLayers`,
`changedSources`, and `warnings` are empty, and `styleAuthority` is
`'not-checked'`. Its `diff` is `[]` unless the caller supplies `diff: false`.

This does not relax validation elsewhere: `inspectStyle` with
`action: 'validateTransaction'` remains strict and rejects an empty transaction
with `INVALID_INPUT`.

## Output/result limits

The complete successful or failed JSON result envelope is limited to
**1,048,576 UTF-8 bytes**. Success projections preserve source order, cap
ordinary items at 100 and ordinary warnings at 20, reserve a
`COMPACT_OUTPUT_TRUNCATED` warning when needed, and omit oversized values or
items atomically. A feature query's `maxSerializedBytes` can lower this budget,
never raise the 1 MiB cap. Failure messages are capped at 4,096 UTF-8 bytes and
failure details are bounded as well.

No AI result contains a complete authoritative Style document or a `data.style`
field. Read a complete Style through `/core` or your MapLibre Map instance.

## Migration example

```ts
// Removed
import { createCompactMapLibreStyleTools } from 'maplibre-style-tools';

const { applyStyleOperations } = createCompactMapLibreStyleTools({ getMap });
await applyStyleOperations.execute({
  operationsJson: '[{"layerId":"roads","paint":{"line-color":"#fff"}}]',
});

// New
import { createMapLibreStyleTools } from 'maplibre-style-tools/ai';

const { applyStyleTransaction } = createMapLibreStyleTools({ getMap });
await applyStyleTransaction.execute({
  transaction: {
    operations: [{
      op: 'setLayerProperties',
      layerId: 'roads',
      paint: { 'line-color': '#fff' },
    }],
  },
});
```
